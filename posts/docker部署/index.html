3.3 Docker 部署（详细步骤）

3.3.1 适用场景与基本概念

Docker 把应用和运行依赖打包成镜像，用容器运行；Docker Compose 用一个 YAML 文件描述前端、后端、数据库之间的关系。

适合：

  • 希望本地、测试、生产环境一致；
  • 项目依赖多，不想在服务器逐项安装 Python/Node；
  • 希望一条命令启动整套服务；
  • 团队协作和持续部署。

需要理解：

  • 镜像：应用模板，只读；代码变化后需要重新构建；
  • 容器：镜像的运行实例；
  • 数据卷 volume：保存 MySQL 数据等持久内容，删除容器不等于删除数据；
  • 网络 network：容器之间通过服务名访问，例如 api、db；
  • 端口映射：127.0.0.1:8080:80 表示只在本机暴露 8080，转发到容器 80。

预期：

  • 80/443 有 Nginx 监听；
  • 8080 只监听 127.0.0.1；
  • 8000 和 3306 在宿主机上最好没有公网监听；
  • 阿里云安全组只开放 80、443 和受限的面板/SSH 端口。

Docker 发布端口可能绕过部分 ufw 规则。最稳妥的做法是：端口映射明确写成 127.0.0.1:8080:80，数据库和 API 不写 ports，再用阿里云安全组做外层兜底。
